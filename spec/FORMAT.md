# Формат хранилища KouTube, схема 1

Единый источник правды для Android (KouTube) и Windows (KouTube на ПК). Правила слияния проверяются общими тест-кейсами из `spec/fixtures/`; тесты обеих программ прогоняют одни и те же файлы.

## 1. Хранилище

Хранилище — любая папка, внутри которой лежит `.koutube/`:

```
<root>/
├── <папки с видео>          ← существующие (например ВИДОСИКИ/) или Videos/, Shorts/
└── .koutube/
    ├── storage.json
    ├── devices/<deviceId>.json   (+ .tmp/.bak — см. §4)
    └── thumbs/<ytId|fileKey>.jpg
```

Сканируются **только** папки из `storage.json → folders`. Остальное на носителе (музыка, документы) приложение не читает и не трогает.

## 2. Конверт (обязателен для всех JSON в `.koutube/`)

```
{"sha256":"<64 hex>","body":<JSON>}
```

- `sha256` считается от UTF-8 байтов текста `<JSON>` ровно в том виде, в каком он записан в файл.
- Писатель формирует строку так: префикс `{"sha256":"` + хэш + `","body":` + тело + `}`.
- Читатель проверяет префикс фиксированной длины (84 символа: 11 + 64 + 9), берёт подстроку от 84-го символа до последней `}` (не включая её), сверяет хэш и только после этого разбирает JSON. BOM не пишется.
- Канонизация JSON не нужна: хэшируются байты как есть.

Время везде в миллисекундах Unix (UTC), тип `long`. Ключи в camelCase. Неизвестные поля читатель игнорирует.

## 3. storage.json

```json
{
  "schema": 1,
  "storageId": "8f0c2d4e-…",
  "name": "YOUNIKAR",
  "updatedAt": 1760280000000,
  "folders": [ { "path": "ВИДОСИКИ", "role": "auto" }, { "path": "Shorts", "role": "short" } ],
  "downloadTo": { "video": "ВИДОСИКИ", "short": "Shorts" },
  "budget": { "totalBytes": null, "reserveBytes": 5368709120, "shortsShare": 0.2 }
}
```

- **`folders[].path`** — путь относительно корня хранилища, разделитель `/`. Значение `"."` — сам корень.
- **`role`** — `video`, `short` или `auto`.
- **`budget.totalBytes`** — сколько всего выделено под KouTube. `null` значит «всё, кроме `reserveBytes`».
- **Слияние:** файл целиком; побеждает больший `updatedAt`.

## 4. Надёжная запись (одинаково для SAF, MTP и обычных папок)

Запись `X`:
1. Записать `X.tmp` целиком и сбросить его на диск.
2. Если `X` существует: удалить `X.bak`, переименовать `X` → `X.bak`.
3. Переименовать `X.tmp` → `X`.

Чтение `X`: прочитать все существующие `X`, `X.tmp`, `X.bak` и взять **проверенный** (§2) кандидат с наибольшим `body.writtenAt` (для `storage.json` — с наибольшим `updatedAt`). Если проверку не прошёл ни один, файл считается повреждённым. Тогда показываем сообщение, данные этого устройства берём из его локальной копии, а сам файл перезаписываем при следующей записи.

## 5. Файл устройства `devices/<deviceId>.json`

Каждое устройство пишет **только свой** файл; читают все.

```json
{
  "schema": 1,
  "deviceId": "android-1a2b3c4d",
  "deviceName": "Redmi Note 7",
  "kind": "android",
  "app": "KouTube 0.1.0",
  "writtenAt": 1760280000000,
  "caps": { "video": [ { "mime": "video/av01", "hw": false, "maxW": 1920, "maxH": 1080 } ] },
  "items": {
    "f1-516000000-0123456789abcdef": {
      "meta":  { "ts": 1760280000000, "ytId": "2P-bG5Jxcs0", "title": "…", "channel": "…",
                 "url": "https://www.youtube.com/watch?v=2P-bG5Jxcs0", "published": "2026-10-01",
                 "category": "People & Blogs", "durationMs": 6168000, "kind": "video",
                 "width": 1280, "height": 720, "fps": 59.94, "vcodec": "av1", "acodec": "opus",
                 "size": 516000000, "path": "ВИДОСИКИ/Bratishkin Rofls - ….webm",
                 "subs": [ { "lang": "ru", "path": "ВИДОСИКИ/….ru.vtt", "auto": true } ],
                 "thumb": "thumbs/2P-bG5Jxcs0.jpg", "addedAt": 1760280000000,
                 "source": "scan", "sponsorCutMs": 0 },
      "watch": { "ts": 1760280000000, "status": "started", "posMs": 123000,
                 "coverage": "<base64>", "lastWatchedAt": 1760280000000, "finishedAt": null },
      "file":  { "ts": 1760280000000, "state": "present", "at": 1760280000000, "reason": null },
      "flags": { "ts": 1760280000000, "keep": false, "noAutoRedownload": false, "redownload": false }
    }
  }
}
```

### 5.1 Ключ ролика — `fileKey`

`f1-<size>-<hex16>`, где `hex16` — первые 16 hex-символов SHA-256 от конкатенации первых 16 384 и последних 16 384 байтов файла. Если файл меньше 32 768 байтов, хэшируется весь файл. Ключ не зависит от имени и пути и одинаково считается на обеих платформах. Пример: `f1-516000000-0123456789abcdef`.

YouTube ID — атрибут `meta.ytId`, не ключ. Он может появиться позже, когда Manager распознает старый файл.

### 5.2 Группы и поля

| Группа | Поле | Значения |
|---|---|---|
| meta | `kind` | `video`, `short` |
| meta | `source` | `scan` (найден сканером), `manager` (скачан Manager-ом), `ytdlnis` (распознан по тегам) |
| watch | `status` | `new`, `started`, `finished` |
| watch | `coverage` | битовая карта 5-секундных отрезков, реально проигранных не в режиме сна; бит *i* = отрезок [5i, 5i+5) с; base64, младший бит первого байта = отрезок 0 |
| file | `state` | `present`, `deletedAfterWatch`, `deletedByUser` |
| flags | `keep` | «не удалять после просмотра» |
| flags | `noAutoRedownload` | ставится при досмотре и при ручном удалении |
| flags | `redownload` | «Скачать снова» — запрос к Manager |
| flags | `rating` | `1` 👍, `-1` 👎, `0` нет — на этом учатся рекомендации |
| meta | `avatar` | картинка канала внутри `.koutube`, например `avatars/UC….jpg` (её скачивает ПК) |
| meta | `tags` | теги видео с YouTube (их сохраняет ПК при загрузке) — по ним поиск на телефоне находит тему |
| meta | `comments`, `commentCount` | самые популярные комментарии `comments/<id>.json` — массив `{a: автор, t: текст, l: лайки, ts: время (с), p: закреплён, u: автор канала}` — и сколько их у видео всего |

«Пропал» (`missing`) **не хранится**: это вычисляемое состояние — `file.state == present`, но сканер файла с таким ключом не нашёл. Так устройство, которое ещё не увидело чужое удаление, не может затереть `deletedAfterWatch` своим «пропал».

## 6. Слияние

1. Записи объединяются по `fileKey` из всех файлов `devices/*.json` хранилища и из локальной копии устройства.
2. Для каждой группы (`meta`, `watch`, `file`, `flags`) побеждает версия с наибольшим `ts`. При равенстве — версия из файла с бо́льшим `deviceId` (порядковое сравнение строк).
3. Если группы нет нигде, действуют значения по умолчанию: `watch.status = new`, `posMs = 0`; `file.state = present`; все `flags = false`.
4. **Правило писателя.** Меняя поле, устройство записывает группу целиком: слитое значение + своё изменение, `ts = max(сейчас, слитый ts + 1)`. Поэтому группы, которые устройство не меняло, оно не переписывает.
5. В своём файле устройство хранит только записи, в которые оно хоть раз писало.

## 7. Защита от повторной загрузки (Manager)

YouTube ID не качается автоматически, если у любой записи с этим `ytId`:
- `flags.noAutoRedownload == true`, **или**
- файл есть в каком-либо хранилище.

Исключение — запись, у которой `flags.redownload == true` («Скачать снова»). После успешной загрузки Manager снимает у старой записи `redownload` (`noAutoRedownload` остаётся) и создаёт новую запись с новым `fileKey`.

Тот же список Manager передаёт в yt-dlp через `--download-archive` (строки `youtube <id>`), это вторая страховка.

## 8. Сканер

- **Видео:** `.mp4 .m4v .mov .webm .mkv .3gp .ts .flv`. Пропускаются имена, начинающиеся с `.`, и окончания `.part .tmp .ytdl .ktpart`.
- **Сопутствующие файлы** — по общему базовому имени `X.<ext>`:
  - обложка: `X.jpg`, `X.jpeg`, `X.png`, `X.webp`;
  - субтитры: `X.<lang>.vtt`, `X.<lang>.srt`;
  - метаданные: `X.info.json`.
- **Тип ролика** при `role = auto`: если `url` содержит `/shorts/` → `short`. Иначе `height > width` и `durationMs ≤ 180000` → `short`. Иначе `video`.
- **Название и канал** без тегов берутся из имени файла по шаблону `<канал> - <название>`. Полноширинные символы, которыми yt-dlp заменяет запрещённые, возвращаются: `？：｜＊＂＜＞⧸＼` → `?:|*"<>/\`.

## 9. Удаление

Телефон сам ничего не удаляет: досмотренное только помечается (`watch.status = finished`). Удаляет KouTube на ПК — при подключении носителя он показывает досмотренные незакреплённые (`flags.keep = false`) видео и удаляет отмеченные пользователем, ставя `file.state = deletedAfterWatch`. Вручную удалить видео можно и на телефоне (меню ⋮ → `deletedByUser`).

Правила для любого удаления

Удалять можно только файл, который одновременно:
- лежит внутри папки из `folders`;
- зарегистрирован записью с этим `fileKey`;
- даёт тот же `fileKey`, если пересчитать его перед удалением.

Папки не удаляются никогда. Сопутствующие файлы (§8) удаляются только если это включено в настройках.

## 10. Совместимость

Изменение, несовместимое со схемой 1, требует `schema: 2`. Читатель, встретивший незнакомую схему, файл не перезаписывает и показывает «нужна новая версия приложения».
